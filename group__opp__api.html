◆ BT_opp_client_exchange_business_card

#define BT_opp_client_exchange_business_card (   opp_handle,
  opp_req_info,
  more,
  actual 
)    opp_client_push_object ((opp_handle), (opp_req_info), OPP_OP_EXCH_BUSINESS_CARD, (more), (actual))

To exchange a business card with the connected OPP server.

Description:
This API exchanges an object of given format to the already connected OPP server device. First the application should send the contents of the object in the OPP_REQUEST_STRUCT. If the file size exceeds the negotiated OBEX packet length, then BT_opp_client_send_request() can be used to push remaining part of the object. The application will be notified each time the OPP server responds to the request The application can take further actions depending on the notification.

The notification that are given to the application for the push operation is: OPP_CLIENT_EXCH_BUSINESS_CARD_CNF

Parameters
[in]opp_handleValid OPP instance handle.
[in]opp_req_infoThis structure contains the type the business card to be pulled.
[in]moreIt Indicates if application has remaining object still to be sent or it is the complete object content 1 - Object part remaining 0 - No more file part remaining
[out]actualContains the actual number of bytes of BODY header, if any included in the request, that is packed for transmission.
Returns
API_SUCCESS or one of the error codes as defined in BT_error.h.
Note
Establish the OPP connection to a OPP server through BT_opp_client_connect() API before using this API.

◆ BT_opp_client_connect()

API_RESULT BT_opp_client_connect ( OPP_HANDLE *  opp_handle,
OPP_CONNECT_STRUCT *  opp_connect_info 
)

To establish connection to the OPP server.

Description:
This API establishes the OBEX connection with the remote OPP server. OPP client calls the registered application callback upon the completion of the connection process (when the OPP server responds with the connection response) with the notification OPP_CLIENT_CONNECT_CNF.
Parameters
[in]opp_handleOPP handle of the client that has to be connected.
[in]opp_connect_infoStructure containing the Bluetooth device address of the OPP server and the local maximum receive capacity (in bytes), RFCOMM server channel and L2capPsm value.
Returns
API_SUCCESS or one of the error codes as defined in BT_error.h.
Note
  1. Before calling this API the application needs to ensure that the OPP client session has been started by calling BT_opp_client_start().
  2. OPP OBEX connection over L2CAP is introduced from OPPv1.2. To have OPP OBEX connection over L2CAP support, enable OBEX_OVER_L2CAP feature flag in BT_features.h
  3. When OBEX_OVER_L2CAP is enabled:
    • For OPP OBEX connection over L2CAP, set the rfcomm server channel value to 0.
    • For OPP OBEX connection over RFCOMM, set the l2cap psm value to 0.

◆ BT_opp_client_disconnect()

API_RESULT BT_opp_client_disconnect ( OPP_HANDLE *  opp_handle)

To disconnect the established OPP connection.

Description:
This API is to disconnect the OPP connection with the remote OPP server. OPP client calls the registered application callback upon completion of this request with the notification OPP_CLIENT_DISCONNECT_CNF.
Parameters
[in]opp_handleValid OPP handle of the client instance to be disconnected.
Returns
API_SUCCESS or one of the error codes as defined in BT_error.h.
Note
OPP client automatically initiates transport disconnection once the OPP disconnection completes and the application shall be notified with OPP_CLIENT_DISCONNECT_CNF and OPP_CLIENT_TRANSPORT_CLOSE_CNF for OPP disconnection and transport disconnection completion respectively. The instance will be stopped after the transport disconnection completion.

◆ BT_opp_client_send_request()

API_RESULT BT_opp_client_send_request ( OPP_HANDLE *  opp_handle,
UINT8  event_type,
UINT16  event_result,
OPP_HEADERS *  opp_headers,
UCHAR  more,
UINT16 *  actual 
)

To send request to the OPP server.

Description:
This API sends the request to the OPP server with the event type and the data given by the application. The application can call this API to continue any operation initiated and to which the first notification has been received. Thus this API shall be called from the OPP application notification callback function with the event type set to the received event.
Parameters
[in]opp_handleValid OPP instance handle.
[in]event_typeEvent type that was received in the application callback, to indicate that the request is the continuation of the operation for which it was notified.
[in]event_resultThis is the status of the request.
[in]opp_headersStructure containing either get request information, in case of get operation or put request information in case of put operation.
[in]moreIndicates if application has remaining of object still to be sent or object complete 1 - Object part remaining 0 - No more file part remaining
[out]actualContains the actual number of bytes of BODY header, if any included in the request, that is packed for transmission.
Returns
API_SUCCESS or one of the error codes as defined in BT_error.h.
Note
Establish the OPP connection to a OPP server through BT_opp_client_connect() API before using this API.

◆ BT_opp_server_send_response()

API_RESULT BT_opp_server_send_response ( OPP_HANDLE *  opp_handle,
UINT8  event_type,
UCHAR  event_result,
OPP_HEADERS *  opp_headers 
)

To send response to the latest request received from the OPP client.

Description:
This API is used to send the response to the requests made by the OPP client. Response to connect, PUSH, PULL, Exchange business card etc. shall be sent through this API. The application shall call this API with the event type of the latest notification received. This indicates the response is for the latest indication received. OPP server shall frame the OBEX specific packets based on the response and associated response data and send it to the OPP client.
Parameters
[in]opp_handleValid OPP handle of the OPP session.
[in]event_typeEvent type that was received in the application callback. This is to indicate that the response being sent is response to the request for which the application was notified.
[in]event_resultThis is the OBEX response code.
[in]opp_headersStructure containing either the connect information in case of connect operation or the response data in case of other operation.
Returns
API_SUCCESS or one of the error codes as defined in BT_error.h.
