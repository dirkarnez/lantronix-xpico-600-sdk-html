UCHAR  ch_type

To initiate connection from the HID device.

Description:
The API is used to initiate connection from the device to the HID host. This API has been provided to allow the application to connect to a HID host, if it wants to. In a general deployment, the device never attempts to connect to a host - so the calling of this API is completely at the discretion of the application.
Parameters
[in]bd_addrbd_addr is the BD ADDR of the remote host.
[in]ch_typeType of channel
Returns
API_SUCCESS or one of the error codes as defined in BLE_ERROR_CODES.

API_RESULT BT_hid_device_init ( HID_DEVICE_INIT_PARAMS *  init_params)

To initialize the HID device profile.

HID Device APIsThe API is used to initialize the HID Device Profile

Description:
The API initializes the HID Device Profile. This API must be called before other operations on the profile are performed. It is important to set the different values of the init_params structure to ensure a correct and predictable behavior of the profile. The init_params are those parameters that may be part of SDP or that affect the functionality of the profile. Please refer to structure definition of HID_DEVICE_INIT_PARAMS for more detailed description of the different parameters that must be initialized before passing it to this API.
Parameters
[in]init_paramsPointer to structure describing the initialization parameters for the profile.
Returns
API_SUCCESS or one of the error codes as defined in BLE_ERROR_CODES.

◆ BT_hid_device_register()

API_RESULT BT_hid_device_register ( HID_DEVICE_CALLBACK_STRUCT *  hid_device_cb_struct)

To register callbacks with the HID Device Profile.

Description:
The API is used to register profile callback functions. The profile callback functions are a way by which the calling application is given information about the various events that may be occurring at the profile level. Please refer to the structure hid_device_cb_struct for a more detailed explanation of the call back. The callback functions are: i)hid_device_get_request:relays HID GET_ requests to the application ii)hid_device_get_request:relay SET_ requests, HID_CONTROL messages and HID Host OUT reports. iii)hid_device_events :Callback function to relay HID Device Profile Specific events
Parameters
[in]hid_device_cb_structPointer to structure storing the profile callbacks.
Returns
API_SUCCESS or one of the error codes as defined in BLE_ERROR_CODES.
Note
NULL parameters passed to the function imply no callbacks will registered with the profile.

◆ BT_hid_device_send_report()

API_RESULT BT_hid_device_send_report ( UCHAR *  report_data,
UINT16  report_size 
)

To send INTERRUPT reports to the remote host.

Description:
The API is used to send INTERRUPT reports to the remote host. Note that the API takes care of appending appropriate BT_HID headers t the report_data. The input report_data must be formatted correctly only as per the USB HID specifications.
Parameters
[in]report_dataThe HID Report. The report data is constructed from the data read from the device controller and conforms to the USB HID report format. This function will append the necessary BT HID protocol headers.
[in]report_sizeSize of the Report.
Returns
API_SUCCESS or one of the error codes as defined in BLE_ERROR_CODES.

◆ BT_hid_device_send_response()

API_RESULT BT_hid_device_send_response ( UCHAR  response_type,
UCHAR  response_status,
UINT16  response_len,
UCHAR *  response_data 
)

To send responses to the HID Host.

Description:
The API is used to respond to the HID host requests. Whenever a HID protocol request (e.g. GET_PROTOCOL, SET_PROTOCOL) comes from the host, this information is relayed to the application that can then decide how to respond to the request.
Parameters
[in]response_typeIdentifier for type of response.
[in]response_statusStatus of the response - successful/ erroneous.
[in]response_lenSize of the response packet buffer.
[in]response_dataResponse packet buffer.
Returns
API_SUCCESS or one of the error codes as defined in BLE_ERROR_CODES.
Note
The API takes care of appending appropriate BT_HID headers to the response.
