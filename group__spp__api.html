◆ BT_spp_connect()

API_RESULT BT_spp_connect ( SPP_HANDLE  spp_handle,
UCHAR *  bd_addr,
UINT8  server_channel 
)

This API establishes service level connection between SPP Dev A and SPP Dev B.

Parameters
[in]spp_handleHandle identifying a SPP connection.
[in]bd_addrBluetooth Device address of the remote SPP Device with which connection needs to be established.
[in]server_channelThe server channel in which connection has to be initiated.
Returns
API_RESULT: API_SUCCESS: Indicates connection procedure initiated successfully SPP_ERR_INVALID_STATE: Cannot process user request. API called in wrong SPP State. SPP_ERR_MAX_CONNECT_LIMIT_REACHED: SPP already connected to maximum number of peers. Cannot initiate the SPP connection.

◆ BT_spp_init()

API_RESULT BT_spp_init ( SPP_APPL_EVENT_NOTIFY_CB  application_cb_ptr)

This API registers the application callback function with the SPP and initializes the Serial Port Profile.

Parameters
[in]application_cb_ptrApplication callback function pointer.
Returns
API_RESULT: API_SUCCESS: Indicates Serial Port profile initialized successfully SPP_ERR_NULL_PARAMETER: Indicates application is trying to register NULL as callback. SPP_ERR_MUTEX_INIT_FAILED: Indicates initialization failed due to failure to initialize mutex.

◆ BT_spp_start()

API_RESULT BT_spp_start ( UCHAR  server_channel,
SPP_HANDLE *  spp_handle 
)

This API starts the SPP instance. SPP implementation starts listening on the RFCOMM Channel specified. It enables the application to use the service of the Serial Port profile.

Parameters
[in]server_channelThe RFCOMM server channel in which the SPP device will be listening for peer initiated connection.
[in]spp_handleHandle identifying a SPP connection.
Returns
API_RESULT: API_SUCCESS: Indicates SPP started successfully SPP_ERR_INVALID_STATE: Cannot process user request. API called in wrong HS State. SPP_ERR_NO_FREE_ENTITY: Cannot Start. Free entity not available to allow incoming connections.
See also
BT_error.h

◆ BT_spp_stop()

API_RESULT BT_spp_stop ( SPP_HANDLE  spp_handle)

This API stops the SPP service function on the local device. Existing active SPP connection if any will be released.

Parameters
[in]spp_handleHandle identifying a SPP connection.
Returns
API_RESULT: API_SUCCESS: Indicates SPP switched off SPP_ERR_STOP_PENDING: In the process of releasing active connections, wait until event is indicated in the callback.
